# 从这里开始

只想先花 10 分钟了解整套教程？先读 [[00-首页/10 分钟 Quick Start]]；准备安装环境、动手时再回到本页。

这套教程面向想理解 AI Agent 系统的后端开发者，默认用 **Node.js + TypeScript** 动手，配 **Java/Spring** 对照。你不需要先学 Python、机器学习数学或新框架；先理解一条请求如何经过模型、工具和运行控制，再逐层加能力。

## 第一次只做三件事

1. 花 10 分钟读 [[00-首页/贯穿案例：重复扣款工单]] 的用户请求、组件职责和主路径。
2. 跑下面的离线实验，观察模型“提议查询”与程序“真正查询”的两条事件。
3. 打开 [[00-首页/学习路线]]，从第 1 周开始；把不懂的词放进 [[07-术语与资源/问题清单]]，需要时查 [[07-术语与资源/Agent 术语表]]。

第一次不必读完所有专题。首页的难点案例和生产专题是按需返回的索引。

## 无密钥也能跑的第一次实验

建议安装 Node.js 24 或 22 LTS，并使用随附 npm；版本维护状态以 [Node.js 官方发布表](https://nodejs.org/en/about/previous-releases) 为准。实验使用 `tsc` 编译，再运行 JavaScript，不依赖 Node 是否原生支持 `.ts`。以下命令均在仓库根目录执行：

```powershell
node --version
npm --version
npm --prefix labs/01-agent-runtime/typescript ci --ignore-scripts
npm --prefix labs/01-agent-runtime/typescript run start -- --scenario success
npm --prefix labs/01-agent-runtime/typescript run evaluate
npm --prefix labs/01-agent-runtime/typescript test
```

首次 `npm ci` 需要联网安装锁定的开发依赖；之后实验不调用网络，也没有第三方运行时依赖。不需要全局安装 TypeScript。Windows 若 PowerShell 策略拦截 `npm.ps1`，可用 `npm.cmd` 执行同一命令，无需为此放宽整个系统的执行策略。

成功场景应看到：创建任务 → 模型请求读取订单 → 工具校验与返回 → 模型形成回复。固定场景评测应报告 12 条通过，单元测试应通过。完整字段、其他场景和练习见 [[labs/01-agent-runtime/README|离线实验说明]]。

> [!important] 这个实验能证明什么
> Fake model 按预设脚本输出，订单数据也是合成的。12 条通过证明这些示例的 Runtime 控制行为符合测试，不能证明真实模型理解能力、真实延迟、费用或生产可靠性。接入真实模型后，要重新评测。

## 然后怎样接真实模型

在 [[05-项目实战/01-Minimal Chatbot]] 中完成第一次 API 调用时，先固定一个供应商、一个模型版本和一种消息 API。教程中的 `logical-model-v1` 是占位名，不能直接发送给供应商。

建议依次完成：

1. 从所选供应商官方控制台确认接口地址、账号可用模型和凭据。
2. 按官方文档安装 SDK，锁定依赖版本；凭据放本地环境或服务端密钥管理，不写进代码和实验数据。
3. 只发一个短问题，检查 HTTP/响应状态、完整文本和 usage。
4. 再加统一的 [[01-基础/02-Prompt 与结构化输出#工单分类契约|工单分类契约]]，做解析和业务校验。
5. 最后接流式、取消、工具。对照 [[01-基础/03-模型 API 与消息协议]] 处理不同类型的响应。

## 按你的技术栈走

- **TypeScript 主线**：先读实验里的 `Runtime.run()`、模型和工具接口，用 `async/await` 理解完整循环；框架有明确收益时再看 LangGraph 的 JavaScript/TypeScript 资料。
- **Java 对照**：把 Runtime 对应到应用 Service，模型/工具适配对应到接口实现，输入输出对应到 DTO/record，权限对应到服务端认证上下文。之后按现有 Spring 项目需要看 [[04-框架与生态/Spring AI 能力边界]]。
- **只选一种语言也能完成四个项目**：不要求为了练习搭一套 TypeScript + Java 微服务。若已有 Java 业务服务，可以先复用其受控只读 API；不要绕过已有鉴权直接连接数据库。

具体类型、校验和异步写法见 [[03-工程实践/TypeScript 与 Java 实现对照]]。Python 实验和 Python 文档检查器只是可选参考/维护工具，不是教程主线的先修要求。

## 卡住时先定位哪一层

| 现象 | 先检查 | 不要据此得出的结论 |
| --- | --- | --- |
| 找不到 `node` / `npm` | 安装路径、终端是否重开；Windows 可试 `npm.cmd` | 教程代码逻辑坏了 |
| 找不到 `tsc` / 编译失败 | 是否在实验包执行过 `npm ci`，Node 版本与完整报错 | 必须全局安装编译器或直接运行 `.ts` |
| 401 / 鉴权错误 | 凭据来源、目标服务、有效期 | 多重试几次会有权限 |
| 模型不存在或不可用 | 实际模型 ID、账号权限、API 类型 | 所有模型都支持同一接口 |
| 429 | 限额、并发、重试提示与总预算 | 无上限立即重试会更快 |
| 没有最终文字 | 状态、拒答、输出上限、工具调用项 | 一定没有产生费用 |
| JSON 合法但内容错 | 标签规则、证据、业务校验 | schema 已通过所以正确 |
| 工具结果为空 | 参数、权限、数据范围、工具错误 | 业务事实一定不存在 |

日志只需要足以定位这些层次的信息，不要打印密钥排错。更深入的问题见 [[07-术语与资源/常见困惑与排错]]。

## 怎么算学会一章

用四件东西自测：一句自己的解释、一个最小例子、一个失败分支、一个可检验结果。例如学完 RAG，能解释“找证据再回答”，也能证明一条无答案题为什么应该拒答。

练习后的“示例答案”用于比对思路，不要求逐字相同。假设数据仅用来理解计算方式；自己的实验结果应保存在 [[99-模板/项目实验模板]]，注明样本和版本。

## 三种阅读深度

| 目标 | 读到哪里 | 应留下什么 |
| --- | --- | --- |
| 先理解 | 基础、核心机制、贯穿案例 | 能解释职责和失败原因 |
| 能动手 | 四项目的基础与标准层 | 可运行代码、固定样本、trace |
| 准备生产 | 工程、安全、评测和生产加餐 | 权限/恢复验证、真实环境评测和运维方案 |

项目中的生产加餐可以后做，但一旦接入私有数据或真实写操作，相关权限与副作用控制就必须具备，不能以“还在学习”为由跳过。
