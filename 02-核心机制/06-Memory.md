# Memory

## Memory 不是聊天记录堆积

Memory 是 Agent 为后续决策保存、选择和读取状态的机制。它需要写入规则、检索规则、过期策略和用户控制。

## 常见层次

| 类型 | 保存什么 | 生命周期 |
| --- | --- | --- |
| 工作记忆 | 当前任务步骤、中间结果 | 一次 run |
| 会话记忆 | 对话摘要、未完成事项 | 一个 session |
| 长期记忆 | 稳定偏好、已确认事实 | 跨 session |
| 外部状态 | 订单、工单、代码等真实业务数据 | 由外部系统管理 |

## 写入原则

- 只保存未来确实有用且允许保存的信息。
- 区分用户原话、模型推断和已验证事实。
- 给长期记忆设置来源、时间、置信度和删除方式。
- 敏感信息默认不进入长期记忆。

## 读取原则

不要把全部历史塞回上下文。根据当前任务检索少量相关记忆，并标注它可能过期。真正的业务状态应通过 [[02-核心机制/04-Tool Calling|工具]] 读取源系统。

## 先区分 State、History 与 Memory

- **State**：任务执行必须依赖的确定性字段，如当前步骤、购物车 ID、审批状态。
- **History**：发生过的原始事件或消息，用于审计和回放。
- **Memory**：从历史中选择或提炼、供未来任务使用的信息。

不能只保存聊天消息再让模型“自己找状态”。例如支付流程的 `paymentConfirmed` 必须是受控状态字段，而不是隐藏在某句自然语言里。

## Memory 写入管线

```mermaid
flowchart LR
    Event["对话/事件"] --> Candidate["提取候选记忆"]
    Candidate --> Policy["隐私与价值判断"]
    Policy --> Verify["来源/置信度/用户确认"]
    Verify --> Store["带元数据写入"]
```

一条长期记忆建议包含：主体、内容、类型、来源、创建时间、最后确认时间、置信度、过期时间、可见范围和删除状态。

## Memory 读取管线

```mermaid
flowchart LR
    Task["当前任务"] --> Query["生成检索条件"]
    Query --> Filter["用户/租户/时间过滤"]
    Filter --> Rank["相关性排序"]
    Rank --> Budget["按上下文预算选择"]
    Budget --> Prompt["标注为记忆上下文"]
```

检索到的记忆不是最高优先级指令，也不一定仍然正确。时间敏感内容需要源系统重新确认。

## 摘要记忆的风险

对话摘要能压缩 token，但会丢失细节并混入模型解释。建议保留原始事件 ID，让摘要中的重要结论可以追溯。更新摘要时要考虑事实被纠正的情况，避免旧错误永久保留。

## 冲突与遗忘

- 新信息与旧记忆冲突时，不要简单覆盖；记录来源与时间，再按规则选择。
- 用户明确纠正偏好时，应废弃旧版本。
- 到期并不一定物理删除，但不得继续注入上下文。
- 用户应能查看、修改和删除长期个性化记忆。

## 示例：客服助手

| 信息 | 去向 | 原因 |
| --- | --- | --- |
| 用户要求本次用英文 | 会话状态 | 只适用于当前会话 |
| 用户长期偏好中文 | 长期偏好记忆 | 跨会话有用，可由用户修改 |
| 订单 123 已发货 | 不做长期记忆 | 应实时查询订单系统 |
| 本次退款已等待审批 | run state | 决定当前流程下一步 |
| 客户上传的身份证号 | 默认不写记忆 | 高敏感且无长期必要 |
