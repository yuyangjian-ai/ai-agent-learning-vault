# 项目实战总览

## 项目阶梯

| 项目 | 核心能力 | 建议时间 | 完成标志 |
| --- | --- | --- | --- |
| [[05-项目实战/01-Minimal Chatbot]] | API、消息、schema、日志 | 2–3 天 | 稳定输出并可重放 |
| [[05-项目实战/02-Mini Agent CLI]] | 工具、循环、权限、状态 | 1–2 周 | 可控地完成多步任务 |
| [[05-项目实战/03-RAG 知识助手]] | 建库、检索、引用、评测 | 1–2 周 | 有证据回答并能拒答 |

## 每个项目都要交付

- README：目标、范围、启动方式和限制。
- 架构图：组件、数据流、权限边界。
- 测试/评测：正常、边界、失败和攻击样本。
- 运行轨迹：模型版本、Prompt 版本、工具调用、耗时和成本。
- 复盘：最严重的失败、根因、下一版改动。

使用 [[99-模板/项目实验模板]] 记录每次实验；最终把失败样本加入 [[06-评测安全生产/Agent 评测|评测集]]。

## 综合项目

完成前三个项目后，进入 [[05-项目实战/04-客服工单 Agent]]。它把分类、RAG、工具、Workflow、审批、评测和生产化组合成一个受控业务 Agent。

## 项目不是功能清单

每次迭代只改变一个主要变量，并保留基线。比如优化 RAG 时，固定模型和生成 Prompt，只比较切分或检索；优化 Agent Loop 时，固定工具契约，只比较终止和恢复策略。

## 证据包

每个项目最后生成一个 evidence pack：

- 架构和威胁模型
- 版本清单
- 评测数据集与结果
- 3–5 个典型失败 trace
- 成本与延迟报告
- 已知限制和下一步

这比“演示一次成功流程”更能说明你真正掌握了 Agent 工程。

> [!example]- 帮助理解：一个最小 evidence pack
> ```text
> evidence-pack/
>   manifest.yaml
>   eval-baseline.json
>   eval-candidate.json
>   traces/failure-001.json
>   cost-report.md
>   known-limitations.md
> ```
> `failure-001` 通过 run ID 进入评测数据集；修复后使用同一个 eval version 比较 baseline 与 candidate。这样架构、失败轨迹、评测结果和版本变更能形成同一条证据链，而不是几份互不关联的文档。
