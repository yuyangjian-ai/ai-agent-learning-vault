# 可观测性与生产化

## 一次 run 要能回答

- 用户目标是什么，使用了哪个模型和 Prompt 版本？
- 每一步为什么调用这个工具，输入输出是什么？
- 花了多少时间、token 和费用？
- 最终状态是什么，失败发生在哪一层？
- 是否经过审批，谁批准了什么动作？

## 关键遥测

| 类型 | 示例 |
| --- | --- |
| Trace | model call、tool call、retrieval、approval |
| Metrics | 成功率、P95 延迟、成本、循环步数、拒答率 |
| Logs | 结构化错误、run ID、版本、脱敏摘要 |
| Audit | 身份、资源、动作、策略结果、确认记录 |

## 上线检查

- [ ] 模型/Prompt/工具 schema 有版本号和回滚方案。
- [ ] 限流、超时、熔断、重试和降级已定义。
- [ ] 预算同时限制单 run、单用户和全局额度。
- [ ] 长任务支持取消、断点恢复或幂等重跑。
- [ ] 敏感数据有分类、脱敏和保留策略。
- [ ] 评测门禁和灰度发布已接入。
- [ ] 人工接管时能看到完整但合规的上下文。

## 优先告警

安全违规、写工具失败、成本突增、循环耗尽、无答案率突变、特定模型版本质量下降。

## Trace 层次

```text
agent.run
  context.build
    memory.retrieve
    rag.retrieve
  model.call
  tool.call
    policy.check
    external.request
  approval.wait
  model.call
  response.validate
```

每个 span 带 `runId/stepId`、逻辑模型、Prompt/工具版本、状态和耗时。高基数字段如完整参数不适合作为 metrics label；敏感内容默认不进入 span attributes。

## Dashboard

### 质量

任务成功率、无答案率、人工修改率、引用支持率、安全违规。

### 可靠性

各模型/工具错误率、超时率、重试率、循环耗尽、checkpoint 恢复成功率。

### 性能与成本

首 token/P50/P95 总延迟、各阶段耗时、输入输出 token、单任务成本、缓存命中率。

### 业务

工单处理时间、自动解决率、审批等待时间。技术指标必须能映射到真实业务结果。

## SLO 示例

- 99% 只读查询在 15 秒内得到结果或可解释失败。
- 100% 写工具都有审计与有效审批。
- 99.9% run 状态转换不丢失。
- 安全违规预算为 0。

SLO 应区分模型慢、工具慢、审批等待；否则一个总延迟无法指导优化。

## 发布流程

1. 离线回归和安全测试。
2. 使用历史输入做 shadow run，不产生副作用。
3. 小比例 canary，绑定新控制面版本。
4. 比较质量、延迟、成本和失败分布。
5. 自动或人工决定扩大、暂停、回滚。

## Runbook

为模型不可用、工具错误率突增、成本异常、注入攻击和评测下降分别准备 runbook。Runbook 要包含检测信号、立即止损、降级行为、数据查询、负责人和恢复验证。

## 数据隐私

Debug 模式也不能无限记录原文。设计分级采样：普通成功只留元数据，失败留脱敏摘要，特定受控 run 经授权才保留完整内容；所有内容有过期和访问审计。
