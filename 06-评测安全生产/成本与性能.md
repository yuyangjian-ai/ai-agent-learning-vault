# 成本与性能

## 成本组成

```text
总成本 = 模型输入 + 模型输出 + Embedding + Rerank
       + 工具/API + 存储/检索 + 重试 + 评审调用
```

Multi-Agent、Reflection 和重复上下文会让一次用户请求包含多次模型调用，不能只看最终回答 usage。

## 延迟分解

端到端延迟包括排队、Context 构建、首 token、完整生成、工具、检索、审批和重试。为每段建立 span，优化最长路径，而不是笼统说“模型慢”。

## 优化顺序

1. 删除无效循环和无价值调用。
2. 裁剪重复上下文和过大工具结果。
3. 并行真正独立的只读步骤。
4. 对固定任务使用通过评测的小模型。
5. 缓存 embedding、稳定检索和安全的只读结果。
6. 最后再微调模型参数或基础设施。

## 缓存键

模型结果缓存至少考虑模型版本、Prompt 版本、schema、规范化输入、上下文/数据版本、用户权限和工具集合。缺少权限或数据版本会导致跨用户泄露或返回旧事实。

## 降低输入 token

- 动态暴露必要工具，而不是把几十个 schema 全部发送。
- 搜索先返回摘要，再读取具体内容。
- 对话历史使用带引用摘要。
- RAG 去重、rerank 后只保留高价值证据。
- 稳定前缀在供应商支持时利用 prompt caching，但仍要跟踪命中条件。

## 性能门禁

每次发布比较 P50/P95/P99、首 token、总 token、工具次数和单任务成本。平均值会掩盖长尾；质量不达标时，成本下降也不能算优化成功。

## 练习

对一个 8 步 Agent trace 做成本归因，找出最大的三项。分别设计“减少调用”“缩短上下文”“改用小模型”的实验，并说明可能损失的质量。

> [!example]- 示例答案（假设数据）
> 成本前三项：4 次规划/反思调用占 42%，重复携带完整历史占 31%，最终大模型生成占 18%。
>
> - 减少调用：只在工具结果改变关键假设时 re-plan，调用从 8 次降到 5 次；风险是复杂失败下少一次纠错机会。
> - 缩短上下文：历史消息改为带引用摘要，输入 token 降低 35%；风险是摘要遗漏早期约束。
> - 小模型：分类和参数抽取改用小模型，大模型只做最终解释；风险是边界工单误分类。
>
> 三个实验分别单独运行，并同时比较任务成功率、安全违规、P95 和成本；质量低于门禁时不接受成本收益。
