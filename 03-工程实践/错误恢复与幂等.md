# 错误恢复与幂等

## 错误分类比重试更重要

| 类型 | 示例 | 策略 |
| --- | --- | --- |
| 暂时性 | 限流、网络抖动 | 退避重试，服从总 deadline |
| 永久性 | 参数非法、资源不存在 | 修正输入或结束 |
| 权限性 | scope 不足、租户不匹配 | 禁止重试，返回可操作说明 |
| 不确定性 | 写请求超时 | 查询幂等结果，不直接重放 |
| 逻辑性 | 重复步骤、计划不可行 | 换策略或请求用户输入 |
| 预算性 | token/步骤/费用耗尽 | 保存部分结果并终止 |

## 幂等键

对于创建、发送、支付等动作，Runtime 为“同一次业务意图”生成稳定键。工具端保存键与结果；同一个键再次到达时返回第一次结果，而不是重复副作用。

键应绑定规范化业务参数和主体，不能让模型自由生成。修改参数后必须产生新键并重新审批。

## 重试预算

总 deadline 120 秒，不代表模型和每个工具都能各重试 120 秒。Runtime 应把剩余时间分配给当前步骤，重试前检查剩余预算是否足以完成。

## 补偿不是回滚

跨系统操作通常没有数据库事务。发送错误邮件无法“回滚”，只能补发更正；已经退款可能需要新的扣款流程。Workflow 应把补偿动作显式建模，并考虑补偿本身失败。

## Circuit Breaker 与降级

外部服务持续失败时，熔断能避免所有 Agent 反复调用。降级必须保持语义诚实：实时订单服务不可用时，可以返回“暂时无法确认”，不能拿旧 Memory 冒充当前状态。

## Chaos 练习

在测试环境随机注入：模型 429、工具超时、工具成功但响应丢失、数据库乐观锁冲突、用户在审批后取消。检查状态是否一致、是否重复副作用、trace 能否定位。
