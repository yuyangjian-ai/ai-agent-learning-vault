# Workflow 与 Agent

## 区别

**Workflow** 的路径主要由代码预先定义；**Agent** 让模型根据当前状态动态选择下一步。实际系统通常是二者结合。

| 选择 | 适合场景 | 优点 | 代价 |
| --- | --- | --- | --- |
| 确定性代码 | 规则明确 | 快、稳定、好测试 | 灵活性低 |
| Workflow | 步骤已知，局部需要模型 | 可控、易观测 | 分支需要维护 |
| Agent | 路径未知，需要探索 | 灵活 | 成本、风险、调试难度高 |

## 推荐决策顺序

1. 普通代码能解决吗？
2. 固定 Workflow 加一次模型判断能解决吗？
3. 只有路径确实无法预定义时，才引入 [[02-核心机制/07-Agent Loop]]。
4. 只有明确需要并行角色或上下文隔离时，才引入 [[02-核心机制/09-Multi-Agent]]。

## 混合架构示例

退款流程可以固定为：读取订单 → 规则校验 → 模型解释异常 → 人工审批 → 确定性退款。模型没有跳过审批的能力。

## 自测

为你的一个业务任务画出状态图，并标记哪些节点必须确定、哪些节点需要模糊判断。能固定的路径越多，系统越容易上线。

> [!example]- 示例答案（参考）
> 以“退款申请”为例：`接收申请 → 意图/原因分类（LLM）→ 查询订单（确定性工具）→ 规则校验（代码）→ 生成解释（LLM）→ 人工审批（确定性状态）→ 执行退款（幂等工具）→ 通知（固定 Workflow）`。只有分类和自然语言解释需要模糊判断。

## 五种常见 Workflow 模式

### Prompt Chaining

把一个大任务拆成固定阶段，例如抽取事实 → 校验 → 生成说明。每个阶段有独立 schema，阶段之间可以设置质量门禁。

### Routing

先判断任务类型，再进入不同的确定性流程。路由器可以是规则、分类模型或 LLM，但候选路径由代码定义。

### Parallelization

并行执行互不依赖的检索或分析，再由确定性代码或合并器汇总。适合降低延迟，不等同于必须使用 Multi-Agent。

### Orchestrator–Workers

编排器动态拆分子任务，Worker 独立执行并返回结构化结果。适合子任务数量和内容无法预先确定的场景。

### Evaluator–Optimizer

生成器产出结果，评估器按 rubric 指出具体问题，再有限修订。必须有最大轮数和停止条件。

## 决策案例：客服退款

| 步骤 | 实现方式 | 原因 |
| --- | --- | --- |
| 识别用户意图 | LLM 分类 | 表达多样、边界模糊 |
| 查询订单 | 确定性工具 | 事实来自源系统 |
| 判断是否符合退款规则 | 业务代码 | 金额与政策必须一致 |
| 解释拒绝原因 | LLM | 需要自然语言表达 |
| 执行退款 | 工具 + 审批 | 高风险副作用 |
| 发送通知 | 固定 Workflow | 顺序和模板已知 |

这类混合设计通常比“让 Agent 自己完成退款”更安全，也比纯规则客服更自然。

> [!example]- 帮助理解：什么任务真的需要动态 Agent
> “只读分析一次陌生服务故障”很难预先固定全部路径：第一条日志可能指向数据库、DNS、证书或配置，下一步要看刚获得的证据。这里可以让模型在受限的日志、指标和配置工具之间动态选择。
>
> 但边界仍然固定：工具只读、最多 8 步、总 deadline 3 分钟、每个结论引用证据。发现修复方案后，真正的配置修改回到固定 Workflow 和人工审批。

## 如何从 Workflow 升级到 Agent

先记录 Workflow 的失败样本。如果大部分失败来自“无法预先判断下一步需要哪个信息”，可以只把该路由节点升级为 Agent，而不重写整个流程。

## 练习

把 [[05-项目实战/03-RAG 知识助手]] 分成 ingestion workflow 和 query workflow，标出模型参与点、确定性节点、失败状态与重试边界。

> [!example]- 示例答案（参考）
> - Ingestion：加载 → 解析 → 结构化切分 → 补充标题摘要（可选 LLM）→ ACL/版本校验 → embedding → 写入临时索引 → 验证 → 原子切换。解析失败不重试；临时网络错误有限重试；校验失败进入 `REJECTED`。
> - Query：鉴权 → 问题改写（可选 LLM）→ 混合检索 → ACL/版本过滤 → rerank → 证据预算 → 生成回答（LLM）→ 引用校验。检索超时可降级到关键词；无证据进入 `NO_EVIDENCE`；引用不支持结论时最多修订一次。
