# Agent 术语表

| 术语 | 通俗解释 | 深入阅读 |
| --- | --- | --- |
| LLM | 根据上下文生成 token 的模型 | [[01-基础/01-LLM 基础]] |
| Fine-tuning（训练微调） | 用训练数据进一步更新模型参数，适配任务或行为；与调整 temperature 这类推理配置不同 | [[01-基础/01-LLM 基础]] |
| Prompt | 交给模型的任务契约和上下文 | [[01-基础/02-Prompt 与结构化输出]] |
| Structured Output | 按 schema 返回可被程序消费的数据 | [[01-基础/02-Prompt 与结构化输出]] |
| Tool Calling | 模型提出工具请求，由 Runtime 执行 | [[02-核心机制/04-Tool Calling]] |
| RAG | 检索外部证据后再生成回答；可用关键词、向量等方式，不限定向量库 | [[02-核心机制/05-RAG]] |
| LLM Wiki | 用 LLM 将资料整理、关联并维护为知识页面；写入外部文件，不等于训练模型，查询仍需选择证据 | [[02-核心机制/10-LLM Wiki]] |
| Embedding | 把内容映射为便于相似度计算的向量 | [[01-基础/04-Embedding 与向量检索]] |
| 向量库/向量索引 | 存储并检索相似向量的组件；不负责生成摘要或判断事实 | [[01-基础/04-Embedding 与向量检索]] |
| Memory | 按规则保存和读取后续决策需要的信息；可包含状态、偏好或长期知识 | [[02-核心机制/06-Memory]] |
| Agent Loop | 决策、执行、观察、再决策的循环 | [[02-核心机制/07-Agent Loop]] |
| Runtime | 承接模型提议、管理状态并执行校验、调度和停止条件的程序 | [[02-核心机制/07-Agent Loop]] |
| Planning | 把目标拆成步骤并动态调整 | [[02-核心机制/08-Planning 与 Reflection]] |
| Reflection | 按标准检查并修订结果 | [[02-核心机制/08-Planning 与 Reflection]] |
| Workflow | 主要由代码预定义的执行路径 | [[03-工程实践/Workflow 与 Agent]] |
| Multi-Agent | 由编排层协调多个角色化执行单元 | [[02-核心机制/09-Multi-Agent]] |
| MCP | AI 应用发现和调用外部能力的协议 | [[04-框架与生态/MCP 概览]] |
| Trace | 一次 run 内各步骤的关联轨迹 | [[06-评测安全生产/可观测性与生产化]] |
| Eval | 用固定样本和标准比较系统质量 | [[06-评测安全生产/Agent 评测]] |
| State | 当前 run 的确定性业务和执行状态 | [[03-工程实践/状态、事件与持久化]] |
| Checkpoint | 可暂停、恢复的状态快照 | [[03-工程实践/状态、事件与持久化]] |
| Run / Job | Run 是一次整体任务；Job 是交给外部系统异步执行的一项工作，两者用 ID 关联 | [[03-工程实践/异步任务与取消]] |
| Lease（租约） | Worker 在有效期内领取任务的资格；过期可重新领取，但旧 Worker 未必已经停止 | [[03-工程实践/异步任务与取消]] |
| Idempotency | 同一业务意图重复执行仍只产生一次效果 | [[03-工程实践/错误恢复与幂等]] |
| HITL | 在审批、补充信息或接管点引入人工 | [[03-工程实践/Human-in-the-loop]] |
| Model Gateway | 统一模型能力、路由、错误和 usage 的边界 | [[03-工程实践/模型网关与路由]] |
| Prompt Injection | 不可信文本诱导模型违反原有规则 | [[06-评测安全生产/Prompt Injection 攻防]] |
| ACL | 访问控制列表，记录哪些身份可对哪些资源做什么；检索证据也要按它过滤 | [[06-评测安全生产/安全与权限]] |
| OAuth | 授权访问框架，让应用获得访问资源的受限凭据 | [[03-工程实践/身份、凭据与委托授权]] |
| OIDC | 建立在 OAuth 2.0 上的身份认证协议，用来确认登录用户是谁 | [[03-工程实践/身份、凭据与委托授权]] |
| Access token | 调用目标资源服务的访问凭据，由可信执行层保管和使用 | [[03-工程实践/身份、凭据与委托授权]] |
| Scope | 凭据允许的一类访问范围，如 `orders:read`；具体订单归属仍需另查 | [[03-工程实践/身份、凭据与委托授权]] |
| Audience / Resource | 凭据面向哪个服务或资源；订单服务的凭据不能随意用于支付服务 | [[03-工程实践/身份、凭据与委托授权]] |
| 委托授权 | 应用在用户授予的范围与自身策略的交集中代表用户行动，并保留身份与动作审计 | [[03-工程实践/身份、凭据与委托授权]] |
| Multimodal（多模态） | 处理文本、图片、音频或视频等不同形式的信息 | [[04-框架与生态/多模态与 Computer Use]] |
| Computer Use | 观察页面或桌面，提出点击、输入等动作，执行后重新观察并验证结果 | [[04-框架与生态/多模态与 Computer Use]] |
| Reranker | 对检索候选进行更精细的相关性重排 | [[02-核心机制/05-RAG]] |
| TP / FP / FN | 先定义要检测的正类：TP 是正确命中，FP 是误报，FN 是漏报 | [[06-评测安全生产/评测指标怎么算]] |
| Precision（精确率） | TP / (TP + FP)：判为正类的结果中有多少真的为正；先定义正类，分母为 0 时另行约定 | [[06-评测安全生产/评测指标怎么算]] |
| Recall（召回率） | TP / (TP + FN)：所有实际正类中找到多少；例如所有该拒答请求中拦住多少 | [[06-评测安全生产/评测指标怎么算]] |
| F1 | 2TP / (2TP + FP + FN)，综合 Precision 与 Recall；仍需分别看误判与漏判代价 | [[06-评测安全生产/评测指标怎么算]] |
| Recall@k | 单题前 k 条命中的去重相关证据数 / 该题全部标注相关证据数；无答案题记 N/A，另报处理质量 | [[06-评测安全生产/评测指标怎么算]] |
| Hit@k | 单题只检查前 k 条是否至少命中一份相关证据，取 0/1；本教程平均值的分母是有答案的评测题数 | [[06-评测安全生产/评测指标怎么算]] |
| P95 | 第 95 百分位；本教程手算将 n 个延迟排序后取第 ceil(0.95n) 个，实际报告需说明算法与样本范围 | [[06-评测安全生产/评测指标怎么算]] |
| SLI | 实际测得的服务质量指标，例如 15 秒内响应的请求比例，需定义窗口与分母 | [[06-评测安全生产/可观测性与生产化]] |
| SLO | 用 SLI 衡量的服务质量目标值或范围 | [[06-评测安全生产/可观测性与生产化]] |
| SLA | 与用户约定服务目标及未达标后果的协议，例如服务补偿；不只是一个监控阈值 | [[06-评测安全生产/可观测性与生产化]] |
| Shadow（影子运行） | 让候选版本旁路处理相同输入以便比较；隔离真实写操作，输出不直接交付用户 | [[06-评测安全生产/可观测性与生产化]] |
| Canary（金丝雀发布） | 先让少量真实流量使用新版本，依据质量、延迟与错误决定扩大或回滚 | [[06-评测安全生产/可观测性与生产化]] |
